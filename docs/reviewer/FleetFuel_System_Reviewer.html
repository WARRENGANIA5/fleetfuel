3. System Architecture

The system uses a client–server, three-layer architecture (presentation, application, data) with the ML model inside the application layer.

BROWSER (HTML + CSS + JS, Bootstrap, Chart.js) | HTTP requests / fetch() JSON every few seconds v FLASK APP (app.py, run by Waitress on the server PC, or Vercel online) |-- Routes & login/role checks (login_required, admin_required) |-- Preprocessing (model/preprocess.py) --> Joblib model --> predicted liters |-- Data layer (db.py): in-memory copy kept fresh by Firestore listeners | v FIREBASE CLOUD FIRESTORE (users, vehicles, trip_records, predictions, ...) GOOGLE COLAB --trains--> linear_regression_pipeline.joblib + metrics --upload--> Flask

5. Database Design (Firestore collections)

Firestore is a NoSQL document database: data is kept in collections of documents (fields like JSON), no tables or SQL. Only the server touches it (with a private service-account key), never the browser.

CollectionStores
usersUsername, full name, email, password hash, role (admin/staff), status (pending/active/rejected).
vehiclesPlate number, brand/model, fuel type, engine power (kW).
trip_recordsDate of travel, plate number, distance (km), fuel consumed (L); link to a prediction.
predictionsFuel requests: vehicle, distance, predicted liters, range, status, liters released, actual fuel, model version.
trip_dataset_changesEdits/deletions made to the online-dataset trips.
notification_dismissalsWhich notifications each user has dismissed/seen.
_counters/_changesChange counter used to tell when data was saved.
Real-time: Firestore snapshot listeners keep an up-to-date copy of each collection in the server's memory. Pages poll the server every few seconds, and those refreshes cost no Firestore reads, so the system stays within the free quota.

6. Machine Learning Model

6.1 The model equation

ŷ = β0 + β1(Distance) + β2(Engine Power) + β3(Fuel Type) + β4(Distance × Engine Power)
  • Dependent variable (y): actual fuel consumed per trip, in liters.
  • Independent variables: Distance (km), Engine Power (kW), Fuel Type (1 = Gasoline, 0 = Diesel).
  • Interaction term: Distance × Engine Power — a bigger engine burns more fuel per kilometre, so the effect of distance depends on engine power.

Fitted equation (original units):

ŷ = −1.7904 + 0.03263(Distance) + 0.03167(Engine Power) + 0(Fuel Type) + 0.000573(Distance × Engine Power)

Fuel Type gets 0 because the final model is trained only on the fleet's operating range — diesel vehicles, 30–400 km, 51–177 kW — so there is no gasoline variation to learn. Centered form (used inside the pipeline): intercept 14.463; distance 0.0873; power 0.1186; interaction 0.000573; centers = 151.58 km and 95.35 kW.

6.2 Pipeline steps (CRISP-DM)

CRISP-DM phaseWhat was done
1. Business UnderstandingGSO needs to estimate fuel per official trip to plan fuel release and detect unusual use.
2. Data UnderstandingMonthly Report of Official Travel (local trips) + vehicle records + open online datasets.
3. Data PreparationMerge trips with vehicles by plate number; add supplementary data; drop missing values and zero distance; remove outliers with the IQR rule on L/100 km within each engine-power group; keep fleet range; encode fuel type; mean-center distance and power; add interaction term.
4. Modeling80/20 train/test split (random_state 42); scikit-learn Pipeline = TermEncoder + LinearRegression (Ordinary Least Squares).
5. EvaluationR², MAE, RMSE on the test set; 5-fold cross-validation; VIF; LINE assumption tests; residual plots.
6. DeploymentSave with Joblib; Flask loads it to predict; new models trained in Google Colab are uploaded through Model Performance (checked before use, no restart).

8. Security Features

  • Password hashing with Werkzeug scrypt — passwords are never stored in plain text.
  • CSRF protection (Flask-WTF) on all forms that change data.
  • Login required and role-based access (login_required, admin_required): staff cannot open admin pages.
  • Login lockout: 5 failed attempts (same username + IP) → locked for 15 minutes.
  • Sessions: 8-hour lifetime, HttpOnly + SameSite=Lax cookies, Secure cookies online (HTTPS); resetting a password signs that user out.
  • Account approval: new sign-ups must be approved by the administrator.
  • Secrets in .env and firebase-key.json — never put in Git; the browser never connects to Firestore.
  • Upload checks: 5 MB limit; an uploaded Colab model is accepted only if it is the expected Linear Regression pipeline and its predictions match its results file.
  • Backups: automatic JSON backup at every start and every 24 hours (newest 30 kept), with restore.

10. Key Terms to Remember

TermSimple definition
Linear RegressionA model that predicts a number as a straight-line (weighted sum) of inputs; fitted by Ordinary Least Squares (minimizes squared errors).
Interaction termProduct of two variables (Distance × Power) letting one variable's effect depend on the other.
Mean-centeringSubtracting the training mean from a variable; lowers VIF without changing predictions.
R² (coefficient of determination)Share of variation in y explained by the model (0–1; higher is better).
MAE / RMSEAverage absolute error / square root of mean squared error, both in liters (lower is better).
K-fold cross-validationData split into 5 parts; train on 4, test on 1, repeat 5 times; checks stability.
VIFVariance Inflation Factor — measures multicollinearity; above 5 = problem.
IQR ruleOutlier if below Q1 − 1.5·IQR or above Q3 + 1.5·IQR.
ResidualActual − predicted value.
Pipeline (scikit-learn)Chains preprocessing and the model into one object, so prediction uses the same steps as training.
JoblibSaves the trained Python model to a file and loads it again.
Flask / WSGI / WaitressPython web framework / standard interface between Python apps and web servers / production server that implements it.
NoSQL / FirestoreDatabase without tables; stores documents in collections, in Google's cloud.
CSRFCross-Site Request Forgery — an attack where another site submits a form as the user; blocked by a secret token.
Serverless (Vercel)Code runs on demand in the cloud without managing a server.

11. Practice Defense Questions

1. What programming language and framework did you use?

Python with the Flask web framework for the back end; HTML5, CSS3, JavaScript, Bootstrap 5 and Chart.js for the front end; Jinja2 for templates.

2. Why Linear Regression and not a more complex model?

Fuel use is close to proportional to distance and engine power, so a linear model fits well (R² 0.89). It is simple, fast, and explainable: each coefficient tells how many liters a km or a kW adds — important for a government office that must justify fuel releases.

3. What database did you use and why?

Firebase Cloud Firestore — a free cloud NoSQL database with real-time listeners, so changes on one computer appear on all others; data is safe even if the server PC turns off.

4. What are your independent and dependent variables?

Independent: distance (km), engine power (kW), fuel type (1 gasoline, 0 diesel) and the Distance × Engine Power interaction. Dependent: fuel consumed per trip (L).

5. How accurate is your model?

R² = 0.8877, MAE = 1.98 L, RMSE = 2.89 L on 6,895 test records; 5-fold cross-validation gives R² 0.8879 ± 0.0015, so it is stable and not overfitting.

6. Why add online data instead of only your own trips?

The 93 local trips came from one diesel van, too few and too narrow to learn the effect of engine power. Open datasets (Fan & Song 2022; EEA 2024, both CC BY 4.0) with the same variables fill this gap.

7. How did you handle multicollinearity?

Distance and engine power are mean-centered before forming the interaction term; all VIFs are 1.01–1.03, below the threshold of 5.

8. Some assumption tests failed. Is the model still valid?

Yes for prediction. With over 30,000 records, tiny deviations become "significant". We use HC3 robust standard errors for heteroscedasticity, and accuracy is confirmed on unseen test data and cross-validation.

9. How does a prediction work in the system?

Staff choose the vehicle and enter the distance; the system reads the vehicle's engine power and fuel type, applies the same preprocessing, and the Joblib pipeline returns the liters with a ± RMSE range. It is saved as a fuel request for admin approval.

10. Does the system retrain itself?

No. Training is done in Google Colab (or train_model.py); the admin uploads the new model and the system validates it before switching.

11. How is the system secured?

Hashed passwords (scrypt), CSRF tokens, login and role checks, login lockout, admin approval of accounts, secure session cookies, secret keys outside Git, server-only database access, and daily backups.

12. How do users access it?

On the GSO network through the server PC (Waitress, port 5000), or online at gsu-fleetfuel.vercel.app.

13. What methodology did you follow?

CRISP-DM: business understanding, data understanding, data preparation, modeling, evaluation and deployment.

14. What is the meaning of the interaction term's coefficient?

0.000573 L per km per kW: each extra kW of engine power adds about 0.00057 L to every kilometre travelled — larger engines burn more per km.
